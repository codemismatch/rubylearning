Vibe Coding with Ruby

Vibe coding flips the usual order of learning. Instead of studying syntax for months before building anything, you describe what you want in plain English, let an AI assistant generate the Ruby code, and learn by running it, breaking it, and directing the next iteration. You are not skipping the learning - you are compressing it into the loop of prompt, run, review, refine.

The quest: rebuild the tools you use every day

The best way to vibe code is to pick targets you already understand as a user. Our favourite format is a guided quest: recreate small working versions of famous software, one per project:
  1. A link shortener - the idea behind Bitly, as a tiny Sinatra app.
  2. A pastebin - store and share text snippets, with expiry.
  3. A URL uptime monitor - a background checker that emails you when a site goes down.
  4. A mini blog engine - posts, Markdown, and an RSS feed (this very site runs on a Ruby static generator).
  5. A chat bot - wire Ruby up to Telegram or Slack and make it answer questions.
Each project is small enough to finish in a weekend and real enough to teach you routing, storage, testing, and deployment.

How a vibe coding session actually works

  1. Describe the outcome, not the code. "Build a Sinatra app with one POST endpoint that accepts a long URL and returns a short code" beats "write some Ruby".
  2. Run everything. Never accept code you have not executed. If it fails, paste the error back - the error message is part of the conversation.
  3. Ask for one change at a time. Small iterations keep the code reviewable and keep you in control.
  4. Interrogate the code. Ask "why did you use before_save here?" or "what breaks if two users submit at once?". The explanation is the lesson.
  5. Refactor with intent. Once it works, ask the AI to make it idiomatic Ruby - then study the diff. That diff is a masterclass.

Where our tracks fit in

Vibe coding gets you building on day one, but reviewing AI-generated code is a real skill - and that is exactly what our free tracks train. Work through Ruby Basics alongside your projects, and graduate to Advanced Ruby when the generated code starts feeling readable instead of magical. Stuck on a concept the AI cannot explain clearly? Ground rules

  • The AI is a fast junior pair programmer, not an oracle. You own the code that ships.
  • If you cannot explain what a generated method does, ask before you accept it.
  • Keep a learning log: one line per session about what surprised you. It compounds.
